# 第二章 LabVIEW 编程环境与数据流

> 这一章是后面所有编程题的地基。三个概念必须清楚：VI 的组成、三个选板、数据流驱动。

<!-- short: ② 编程环境 -->
<!-- en: LabVIEW environment -->

## 2.1 一个 VI 由三部分组成

| 部分 | 作用 | 对应文本语言 |
|---|---|---|
| 前面板 | 图形化用户界面，放输入控件与显示控件 | 程序的输入输出界面 |
| 程序框图 | 图形化源代码（G 代码），由接线端、节点、连线、结构组成 | 函数体 |
| 图标与连线板 | 定义 VI 的接口，供其他 VI 调用 | 函数原型与参数列表 |

当一个 VI 被其他 VI 调用时称为**子 VI**，相当于子程序。前面板控件分两类：**输入控件**只能做输入，**显示控件**只能做输出，二者可以右键互相转换。

## 2.2 三个选板

| 选板 | 出现位置 | 用途 |
|---|---|---|
| 工具选板 | 前面板与程序框图 | 选择操作工具（写值、连线、探针） |
| 控件选板 | 仅前面板 | 添加输入/显示控件 |
| 函数选板 | 仅程序框图 | 添加函数、VI 与结构 |

控件风格有新式、银式、系统、经典四种；函数选板按“编程 → 结构 / 数值 / 字符串 / 数组 / 簇、类与变体”组织。

## 2.3 数据流：LabVIEW 的执行规则

文本语言默认按语句顺序执行；LabVIEW 按**数据流**执行：

::: key 数据流规则
任何一个节点，只有在它的**全部输入数据都有效**时才会执行；执行完毕后把结果送到输出端，驱动下游节点。
:::

因此，两个互不依赖的节点谁先执行**不确定**，也不重要；需要强制顺序时，用顺序结构或人为制造数据依赖（连线）。

::: example 例 2-1 | 判断执行顺序
前面板输入 A、B，程序为 C=A+B−6、D=A/B。两个运算谁先执行？
---
加法与除法都要用 A、B，但彼此没有数据依赖，所以执行顺序不确定，结果不受影响。若必须让加法先算，可把 C 的结果接入除法的一个输入端（制造依赖），或使用顺序结构。考试若问“执行顺序”，标准答案是：由数据流决定，无依赖则顺序不确定。
:::

## 2.4 调试与常用快捷键

| 操作 | 方法 |
|---|---|
| 前面板 / 程序框图切换 | `Ctrl+E` |
| 运行 | `Ctrl+R` |
| 删除错误连线 | `Ctrl+B` |
| 显示即时帮助 | `Ctrl+H` |
| 高亮执行（看数据流动） | 工具条上的灯泡按钮 |
| 单步 | 单步步入 / 步过 / 步出 |
| 断点 | 在连线上右键设置 |

调试三板斧：**高亮执行看数据流、探针看中间值、断点看停在哪**。程序报错时先看错误簇的 status 与 code，再顺着错误线找源头。

::: warn 易错
“连续运行”只适合调试，正式运行会占满 CPU；循环里没有延时会造成死循环，界面无法响应。
:::

::: quiz 自测
两个节点没有数据依赖，LabVIEW 会按什么顺序执行？如果需要固定顺序怎么办？
答案：不保证顺序，由调度决定。需要固定顺序时使用顺序结构，或把前一个节点的输出接到后一个节点的输入，人为建立数据依赖。
:::
